# OpsBox 사용자 가이드

설치와 환경변수는 [README](../README.md)를 참고하세요. 점검 기준 원문은 [예방점검 매뉴얼](INFORMATION_SYSTEM_PREVENTIVE_CHECK_MANUAL.md)에 있습니다. 매뉴얼의 모든 항목이 자동화된 것은 아닙니다.

## 1. 시작하기

브라우저에서 `http://<OpsBox 주소>:3000`을 열고 로그인합니다.

- **로그인 잠금**: 같은 아이디로 15분 안에 5번, 같은 IP에서 20번 실패하면 15분 동안 잠깁니다. OpsBox를 다시 시작하면 풀립니다.
- **HTTPS**: OpsBox는 HTTP로 동작합니다. 사내망 밖에서 쓰려면 앞단에 HTTPS 프록시를 두고 `NODE_ENV=production`으로 실행하세요. 이렇게 하면 세션 쿠키에 `Secure`가 붙습니다.
- **테마**: 사이드바 아래 해/달 버튼으로 바꿉니다. 인쇄는 항상 밝은 양식으로 나옵니다.
  - 삼성 인터넷의 '웹 페이지 어둡게'가 켜져 있으면 테마가 바뀌지 않는 것처럼 보입니다. 이때는 그 기능을 끄세요.

## 2. 메뉴

| 메뉴 | 하는 일 |
| --- | --- |
| 대시보드 | 등록 서버 수, 상태별·유형별 집계, 서버별 최근 점검 결과 |
| 점검 보고서 | 유형 → 서버 → 날짜 순으로 점검 이력을 찾아 보고서를 엶 |
| 설정 › 서버 관리 | 서버 등록·수정, 서버별 점검 정책, 스크립트 다운로드, 결과 파일 올리기 |
| 설정 › 점검 정책 관리 | OS별 기본·WEB·WAS·DB 정책과 항목(점검 만들기 포함) 관리 |
| 설정 › 스크립트 관리 | 점검 항목별 스크립트 조각과 SQL 쿼리 편집, 변경 이력 복원 |
| 설정 › 공통코드 관리 | OS, 역할, 제품, 상태 이름 등 선택값 관리 |
| 설정 › 변경 이력 | 로그인, 서버·정책·템플릿·공통코드 변경, 결과 가져오기, 스크립트 다운로드 기록 |

공통코드의 `value`는 저장된 데이터와 연결되는 값이라 바꾸면 안 됩니다. 화면에 보이는 이름은 `label`에서 바꾸세요.

## 3. 서버 등록

1. **서버 관리 → 신규 서버**에서 아래 값을 입력합니다.
   - 서버 ID: 글자·숫자·`.`·`_`·`-`만 쓸 수 있고 최대 64자입니다. 등록한 뒤에는 바꿀 수 없습니다.
   - 이름, 운영체제, IP, 결과 공유 경로
2. 역할(WEB·WAS·DB·기타)을 하나 이상 고르고, 역할마다 제품을 지정합니다.
   - 한 서버가 여러 역할을 맡으면 한 번만 등록하고 역할을 모두 고릅니다.
   - 이렇게 해도 CPU·메모리·디스크 같은 공통 자원은 한 번만 수집합니다.
3. 저장한 뒤 서버 ID를 눌러 상세 화면에서 점검 정책을 설정합니다.

## 4. 점검 정책

**정책을 서버에 적용하는 순서**
1. **점검 정책 관리**에서 OS·유형별 정책과 그 항목(실행 방식, 스크립트, 결과 표시)을 만듭니다. 기본 정책은 처음부터 들어 있습니다.
2. **서버 상세 → 점검 정책**에서 블록마다 **정책 불러오기 → 적용**을 누릅니다. 블록은 기본점검, WEB, WAS, DB입니다.
3. 서버별 값을 입력하고 **정책 저장**을 누릅니다. 저장한 내용은 다음에 스크립트를 내려받을 때부터 적용됩니다.

**기본점검**
- CPU·메모리·가동시간·디스크는 항상 수집합니다. 사용률 70% 이상이면 주의, 90% 이상이면 위험입니다. 디스크는 가장 높은 볼륨 값을 씁니다.
- 프로세스: 실행 중이 아니면 위험입니다.
- 디렉토리: 경로마다 주의·위험 기준(%)을 정합니다. 주의 기준은 위험 기준보다 작아야 합니다.
- 특정 파일 크기: 주의·위험 기준(MB)을 정합니다. 파일이 없으면 위험입니다.
- 포트: TCP는 LISTEN 상태인지, UDP는 바인딩되어 있는지 봅니다. 서버 안에서만 확인하므로 방화벽이나 원격 접속 가능 여부는 알 수 없습니다. 원격 접속을 보려면 점검 만들기의 '원격 포트 접속'을 쓰세요.
- HTTP: URL과 기대 상태 코드를 정합니다. 최대 10초 기다리며, Linux에서는 `curl`을 씁니다. 코드가 다르거나 접속에 실패하면 위험입니다.

### WEB·WAS

| 항목 | 수집 방법 |
| --- | --- |
| WEB 엔진 상태 | WebtoB는 `wsadmin`에 `wi`, `ci -s`, `st -v`, `st -s`를 보내 RDY/NRDY/BLK로 판정합니다. Apache·Nginx(Linux)는 프로세스와 systemd 상태를 봅니다. |
| WEB·WAS 로그 | 정책에 등록한 폴더(하위 폴더 포함)에서 최근 N일(기본 7일, 1~90일) 로그를 읽어 Fatal·Error/Exception·Warning·HTTP 5xx/4xx를 셉니다. 열지 못한 파일이 있으면 주의입니다. |
| JVM Heap | 같은 JDK의 `jstat -gc`로 계산합니다. 70%·90%가 기준이고, JVM 실행 계정이나 attach 권한이 필요합니다. |
| 배포 상태 | `java`(Node.js는 `node`) 프로세스가 떠 있는지와 시작 시각을 봅니다. |
| Heap Dump | `-XX:HeapDumpPath` 위치에 `.hprof` 파일이 있으면 주의입니다. |
| WEB-WAS 연동, 요청 처리량, Thread·Connection Pool, 장기 수행 Thread, 기동 스크립트 변경 | 관리 주소나 인증 연동이 필요해 미수집으로 남기고 안내합니다. |

### DB

- 항목은 인스턴스·접속, 세션, 데이터 영역, 백업, 아카이브, 트랜잭션 로그, 복제, 기타 사용자 쿼리입니다.
- 항목마다 쿼리 템플릿과 실행 대상을 정합니다. 실행 대상은 한 줄에 하나씩 씁니다.
- 결과는 표로 나옵니다. 첫 열 이름이 `__OPSBOX_STATUS`이고 값이 `Healthy`·`Warning`·`Critical`이면 그 값으로 상태를 판정합니다.
- **기타 사용자 쿼리**에는 여러 쿼리를 고를 수 있습니다. 출력은 최대 200줄, 12,000자까지입니다.
- 접속 계정과 비밀번호는 OpsBox에 저장하지 않습니다. 조회 권한만 있는 점검 전용 계정을 만들어 쓰세요.

| 제품 (OS) | 클라이언트 | 실행 대상 | 인증 |
| --- | --- | --- | --- |
| MSSQL (Windows) | `sqlcmd` | `호스트,포트`, `호스트\인스턴스` (기본 서버 IP:1433) | Windows 통합 인증 `-E` |
| MSSQL (Linux) | `sqlcmd` | `호스트,포트` (기본 localhost) | `SQLCMDUSER`·`SQLCMDPASSWORD`가 있으면 SQL 인증, 없으면 `-E`. 자체 서명 인증서는 `OPSBOX_SQLCMD_OPTIONS='-C'` |
| PostgreSQL | `psql` | `호스트[:포트][/DB]` (비우면 이 서버) | `~/.pgpass` 또는 `PGUSER`·`PGPASSWORD`. root로 실행하면 `postgres` peer 인증 |
| MariaDB | `mariadb`/`mysql` | `호스트[:포트]` 또는 `/소켓경로` | `~/.my.cnf` 또는 `OPSBOX_DB_USER`·`MYSQL_PWD`. root는 unix_socket |
| CUBRID | `csql` | `DB이름[@호스트]` (필수) | `OPSBOX_CUBRID_USER`(기본 dba)·`OPSBOX_CUBRID_PASSWORD` |

**판정 규칙**
- 연결 실패나 쿼리 오류는 위험입니다.
- 권한 부족, 인증 실패, 결과 행 없음, 클라이언트 없음은 미수집입니다.
- PostgreSQL의 WAL 크기를 보려면 `pg_monitor` 권한이 필요합니다.
- MSSQL에서 문자열을 이어 붙이는 쿼리는 `COLLATE DATABASE_DEFAULT`를 붙여야 데이터 정렬 충돌이 나지 않습니다.

**상태 열을 만들 수 없는 쿼리 (Linux 전용)**: CUBRID의 `SHOW` 문처럼 `__OPSBOX_STATUS` 열을 만들 수 없을 때는, 쿼리 위에 주석으로 상태 규칙을 적습니다. 행마다 맞는 규칙 중 가장 높은 상태를 씁니다.

```sql
-- @opsbox-status <Critical|Warning|NotCollected> <열 또는 열A/열B%> <비교> <값>
-- 비교: >=  <=  >  <  =  !=  ~(포함)  in(쉼표 목록)
-- @opsbox-status Warning Num_free_sectors/Num_total_sectors% <= 15
SHOW VOLUME HEADER OF 0;
```

**실제 DB로 확인한 범위**: PostgreSQL 18.7과 MariaDB 13.0.2 기본 쿼리는 실제 DB에서 확인했습니다. CUBRID와 Linux용 MSSQL은 아직 확인하지 않았으니, 운영 DB에 쓰기 전에 먼저 시험해 보세요.

### 점검 만들기 (스크립트 없이 항목 추가)

**점검 정책 관리**에서 항목을 추가할 때 실행 방식을 **점검 만들기**로 고르면, 폼만 채워 점검을 만들 수 있습니다. OpsBox가 정책 OS에 맞는 스크립트 조각을 만들어 줍니다.

| 유형 | 정책에서 입력 | 서버 상세에서 입력 | 판정 |
| --- | --- | --- | --- |
| 명령 결과 숫자 | 준비된 점검 또는 명령, 방향, 주의·위험 기준 | 준비된 점검이 정한 값(예: Ping 대상) | 출력의 첫 숫자를 기준과 비교 |
| 명령 결과 문구 | 명령, 비정상 문구, 정상 문구(선택), 수준 | — | 비정상 문구가 있으면 지정한 수준 |
| 설정값 비교 | 커널 파라미터 / 레지스트리 값, 비교, 기대값 | — | 다르면 지정한 수준 |
| 원격 포트 접속 | 제한 시간(초), 실패 수준 | `호스트:포트` 목록 | 대상 중 가장 나쁜 상태 |
| 파일 최신 여부 | 허용 기간(시간), 파일이 없을 때 수준 | 파일 경로 목록 | 오래되면 주의 |
| 로그 문구 검색 | 문구, 기간(일), 주의·위험 건수 | 로그 경로 목록 | 기간 안에 수정된 파일에서 문구가 든 줄 수 |

**준비된 점검** (고르면 명령과 기준값이 채워집니다)

| OS | 준비된 점검 |
| --- | --- |
| Linux | Swap, I-Node, Ping 손실률, NIC 링크, 소프트웨어 RAID, Multipath, HBA, Cluster(pcs), 커널 파라미터 |
| Windows | Paging File, Ping 손실률, NIC 링크, 물리 디스크, Multipath(mpclaim), HBA, Cluster 노드, 레지스트리 값 |

**동작 규칙**
- 문구는 정규식이 아니라 단순 포함으로 찾고, 대소문자는 가리지 않습니다.
- 명령은 30초가 지나면 멈추고 미수집으로 남깁니다. 명령이 없거나 0이 아닌 코드로 끝나도 미수집입니다.
- 서버별 입력이 비어 있으면 미수집으로 남기고, 무엇을 입력해야 하는지 안내합니다.

**직접 입력 명령은 점검 계정(보통 관리자) 권한으로 그대로 실행됩니다. 읽기 전용 조회 명령만 쓰세요.** 정책을 바꾸면 변경 이력에 남습니다.

**생성된 조각 고치기**
- 만들어진 조각은 스크립트 관리에 `점검 만들기 · <항목 이름>`으로 보입니다.
- 직접 고치면 **직접 편집됨**으로 바뀌고, 그 뒤로는 폼을 바꿔도 덮어쓰지 않습니다.
- 폼 내용으로 되돌리려면 **[폼 기준으로 다시 만들기]**를 누릅니다. 이전 내용은 스크립트 이력에 남습니다.

## 5. 스크립트 실행과 결과 저장

1. 서버 상세의 **점검 스크립트**에서 스크립트를 내려받습니다.
2. 서버에서 실행합니다.
   - **Windows**: 화면에 나오는 한 줄 명령을 스크립트 폴더에서 실행합니다.
     - 결과는 공유 경로 아래 `results/`에 저장됩니다. 다른 곳에 저장하려면 명령의 `$resultDirectory = ''`에 경로를 넣습니다.
     - 저장에 실패하면 스크립트 폴더에 남깁니다.
   - **Linux**: `bash ./<서버ID>.sh /mnt/opsbox/results`처럼 실행합니다. 경로를 생략하면 스크립트 폴더에 저장합니다.
3. 결과 파일이 공유 폴더의 `results/`에 있으면 5분 안에 자동으로 들어옵니다. 다른 곳에 있다면 서버 상세의 **[결과 파일 올리기]**로 올립니다.

실행 계정에는 설정한 경로, 프로세스, 포트를 조회할 권한이 필요합니다. 권한이 없으면 그 항목은 미수집으로 나옵니다.

## 6. 보고서

**보고서 목록**: 유형 → 서버 → 날짜 순으로 펼쳐서 엽니다. 서버명·ID와 기간으로 검색할 수 있습니다.

**보고서 상세**에는 다음 내용이 들어 있습니다.
- 서버 정보, 종합 진단 상태, 자원 사용량 요약
- 점검 항목별 결과: 항목 하나가 상자 하나이고, 역할별(WEB·WAS·DB) 결과는 아래쪽에 따로 나옵니다.
- **비교**: 이전 점검을 고르면 자원 사용량·프로세스·디렉토리를 이전 값과 비교하고, 추세 그래프에 비교 시점(○)을 표시합니다.

**자원 사용 추세**
- CPU·메모리·디스크(가장 높은 볼륨) 사용률을 선으로 그립니다. 기간은 **4주·12주(기본)·26주** 중에서 고릅니다.
- 점검 한 번이 점 하나입니다. 주간점검이면 12주에 약 13개의 점이 찍힙니다.
- 점 위에 값이 나오고, 점을 누르면 그 날짜의 보고서로 이동합니다. 점이 2개보다 적으면 그래프를 그리지 않습니다.
- 주의(70%)·위험(90%) 기준선이 함께 그려집니다.

**인쇄 / PDF**
- A4 세로로 나오고, 표 머리글이 페이지마다 반복됩니다.
- 상태 색까지 인쇄하려면 브라우저 인쇄 설정에서 '배경 그래픽'을 켜세요.

결과에 없는 항목(관리 연동이 필요한 WAS 지표 등)이나 예전 결과 파일에 없는 상세 데이터는 `미수집` 또는 안내 문구로 표시됩니다.

## 7. 스크립트 직접 작성 (고급)

점검 만들기로 안 되는 점검은 **스크립트 관리**에서 항목 조각을 직접 작성합니다. 결과는 아래처럼 남기면 보고서와 종합 상태에 반영됩니다.

- Linux: `opsbox_role_record <역할> <항목ID> <Healthy|Warning|Critical|NotCollected> '<detail JSON>'`
  - 서버별 입력은 `$(opsbox_item_input <항목ID> <키>)`로 읽습니다.
- Windows: `$script:rolePolicyResults += @{ role = '<역할>'; item = '<항목ID>'; status = 'Healthy'; detail = @{ ... } }`

결과를 남기지 않은 항목은 미수집으로 표시됩니다. 스크립트를 저장하면 이전 내용이 템플릿마다 최대 50개까지 이력에 남고, 이력에서 복원할 수 있습니다.
