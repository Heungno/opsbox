# OpsBox 사용자 가이드

OpsBox는 WEB, WAS, DB 서버의 점검 정책을 설정하고, 서버에서 생성한 점검 결과를 조회하는 내부 운영 도구입니다. 화면 스타일과 글꼴은 프로그램에 포함된 리소스와 운영체제 글꼴을 사용하며 외부 CSS나 웹폰트를 요청하지 않습니다.

점검 항목 원문 정리는 [정보시스템 예방점검 매뉴얼](INFORMATION_SYSTEM_PREVENTIVE_CHECK_MANUAL.md)을 참고하세요. 이 문서는 기준 자료이고, 모든 항목이 현재 자동화된 것은 아닙니다.

## 1. 실행

프로젝트 환경에서 의존성을 준비한 뒤 개발 모드로 실행합니다.

```powershell
npm install
npm run dev
```

폐쇄망에서 의존성을 설치할 때는 사내 npm 미러 또는 미리 준비한 `node_modules`/npm 캐시를 사용하세요. 앱 실행 중에는 외부 CSS, 글꼴, 아이콘 CDN을 호출하지 않습니다.

브라우저에서 `http://localhost:3000`을 엽니다. 운영 서버에 배포할 때는 사내 네트워크 정책에 맞게 접근 주소와 포트를 구성하세요.

배포용 파일은 `npm run build`로 `dist/`에 생성합니다. 산출물에는 컴파일된 서버 코드, 화면, 공통코드와 `data/templates.json`이 포함됩니다. 실행 서버에는 Node.js 22 이상과 운영 의존성(`fastify`, `@fastify/static`, `pino-pretty`)이 필요하므로, 실행 서버에 설치하거나 오프라인 배포본에 함께 준비하세요. `dist/`만 이동한 경우 해당 폴더에서 `node server.js`로 실행할 수 있습니다. 개인별 서버 설정은 `data/servers.json`에 저장되며 Git에서 제외됩니다.

## 2. 화면과 탐색

- **대시보드**: 서버 종류별 개수와 최근 점검 상태를 확인합니다.
- **서버 관리**: 서버를 등록하고 상세 화면으로 이동합니다.
- **점검 보고서**: WEB/WAS/DB/기타 유형을 펼쳐 서버별 점검 이력을 조회하고, 유형별 점검보고서 양식으로 결과를 확인합니다.
- 서버 상세 화면에서는 기본 정보, 점검 정책, 스크립트 실행 방법, 점검 이력을 확인합니다.

페이지 좌측 하단의 해/달 토글로 밝은 테마와 어두운 테마를 바꿀 수 있습니다. 선택은 해당 브라우저에 저장되며 페이지 배경과 카드, 표, 입력창, 강조색에도 반영됩니다.

보고서 상세는 공통 점검 결과(종합 상태, 자원, 프로세스, 디스크, 포트, 경로 등)를 먼저 표시하고, 아래쪽에 WEB·WAS·DB 등 서버 역할별 양식을 나눠 표시합니다. **인쇄 / PDF**를 선택하면 A4 세로 레이아웃을 사용하고 표 머리글을 반복하며, 카드와 표 행은 가능한 한 페이지 중간에서 나뉘지 않도록 인쇄 전용 스타일을 적용합니다. 브라우저 인쇄 설정에서 배경 그래픽을 켜면 상태 배지 색상도 포함됩니다.

운영체제, 서버 역할·제품, 포트 프로토콜, 스크립트 종류와 점검 항목의 선택값은 `data/common-codes.json`에서 읽습니다. 항목을 추가하거나 표시 이름을 변경할 때 이 파일을 편집하고 서버를 재시작하세요. `value`는 저장 데이터와 연결되는 코드이므로 기존 코드값은 유지하고, 화면에 보이는 이름은 `label`에서 바꿉니다. 템플릿 내용은 `data/templates.json`, 서버 정보와 정책은 `data/servers.json`에 별도로 저장됩니다.

사이드바의 **스크립트 관리**에서는 점검 항목별 스크립트와 DB 쿼리를 관리합니다. 점검 항목은 서버 기본정보, CPU, 메모리, 가동시간, 디스크, 프로세스, 디렉터리, 파일 크기, 포트, HTTP, WEB, WAS, DB로 나뉩니다. 서버 정책에 필요한 항목만 다운로드 시 하나의 PS1로 조립됩니다. WEB/WAS는 항목별 스크립트를 조립하고, DB는 공통 쿼리 실행기 하나가 정책에 연결된 SQL 템플릿을 실행합니다.
스크립트 관리 화면은 공통 레이아웃 안에서 왼쪽 전체 목록과 오른쪽 편집기를 함께 표시합니다. 목록에서 항목을 고르면 편집기에 열립니다. 종류(점검 스크립트/전체 스크립트/쿼리), 운영체제, 점검 영역(공통 기본/WEB/WAS/DB/시스템), 점검 항목을 조합해 목록을 필터링할 수 있습니다. 편집기에는 외부 라이브러리 없이 SQL, Windows PowerShell, Linux Bash의 주석·문자열·키워드·변수 등을 색상으로 표시합니다. 점검 보고서의 WebtoB 콘솔 출력과 서버 상세의 최종 JSON 미리보기에도 색상 강조를 적용합니다. 수정 중 다른 항목을 선택하면 저장 후 열기, 저장하지 않고 열기, 계속 편집 중 하나를 선택할 수 있습니다. 서버 상세의 정책 버튼에는 선택한 스크립트 이름이 표시됩니다. 선택 모달의 목록은 **기본 제공**과 **사용자 지정**으로 구별합니다. 모달에서 스크립트 수정을 누르면 동일한 스크립트 관리 전체 화면이 열리며, 왼쪽 전체 목록에서 해당 항목이 선택된 상태입니다. HTML과 JavaScript는 화면별 같은 폴더에 두고, 공통 레이아웃·CSS·HTML 조각은 `src/public/shared`에 둡니다.

사이드바는 **대시보드**, **점검 보고서**, **설정**으로 구성됩니다. 설정을 펼치면 **서버 관리**와 **스크립트 관리**를 선택할 수 있습니다. 사이드바 아래 해/달 토글로 밝은 테마와 어두운 테마를 바꿉니다.
스크립트 관리 화면은 `/settings/script-management`에서 엽니다. 화면별 HTML과 JavaScript는 `src/public` 안의 메뉴 이름 폴더에 함께 둡니다. Windows 점검 스크립트와 MSSQL 점검 쿼리는 `data/templates.json`에서 관리합니다. 각 항목을 선택하면 해당 항목의 JSON 결과 예시를 확인할 수 있습니다. 화면에서 저장한 변경 내용도 이 파일에 반영됩니다.

점검 항목 조립은 현재 Windows PowerShell을 대상으로 하며, 스크립트 템플릿 원문과 DB 쿼리는 `data/templates.json`에서 읽습니다. 기본 템플릿 데이터가 저장소에 포함되므로 새 설치도 같은 파일을 사용합니다. Linux 다운로드는 기존 Linux 스크립트를 사용하며, 항목별 Linux 템플릿은 후속 단계에서 추가합니다.

## 3. 서버 등록

1. **서버 관리** 화면에서 **신규 서버**를 선택하면 등록 모달이 열립니다.
2. 서버 ID, 이름, 운영체제, IP 주소, 결과 공유 경로를 입력합니다.
3. **점검 역할 설정** 구역에서 서버 역할(WEB/WAS/DB/기타)을 하나 이상 선택하고, 선택한 WEB/WAS/DB 역할마다 제품을 지정합니다. WEB은 WebtoB, Apache HTTP Server, IIS, Nginx를, WAS는 JEUS, Apache Tomcat, JBoss, Node.js를, DB는 MSSQL, MariaDB, CUBRID, PostgreSQL을 선택할 수 있습니다. Node.js는 애플리케이션 런타임 분류로 WAS 역할에 둡니다.
4. 저장 후 서버 ID를 선택해 상세 화면을 엽니다. 등록과 상세 수정은 같은 입력 모달을 사용하며, 등록 모달에서는 서버 ID를 입력하고 수정 모달에서는 서버 ID가 고정됩니다.

한 서버에 WEB/WAS/DB가 함께 있으면 서버를 한 번 등록하고 역할을 모두 선택합니다. 공통 OS 자원은 한 번 수집되며, 스크립트는 선택된 각 역할의 제품 점검을 함께 수행하고 보고서 트리에는 해당 서버가 각 역할 아래에 표시됩니다. 기존 단일 역할 서버는 자동 호환됩니다. 서버의 운영체제와 일치하는 스크립트를 다운로드해 해당 서버에서 실행해야 합니다. 점검 정책은 서버별로 저장됩니다.

서버 상세의 **점검 정책**은 **공통 기본점검**, **WEB**, **WAS**, **DB** 블록으로 나뉩니다. 공통 블록에는 CPU·메모리·가동시간·디스크와 프로세스·디렉터리·파일 크기·포트·HTTP 정책이 있습니다. 공통 자원 항목은 각 선택 버튼으로, 목록형 정책은 해당 정책의 추가 버튼 옆에서 스크립트를 선택합니다. 스크립트 선택 모달에서 선택된 사용자 템플릿을 바로 수정할 수 있습니다.

WEB 또는 WAS **로그 상태** 항목을 추가하면 해당 서버의 로그 폴더와 조회 기간을 정책에 저장할 수 있습니다. 기본 기간은 최근 7일이며 1~90일로 설정할 수 있습니다. 지정한 폴더와 모든 하위 폴더에서 로그 파일을 읽어 Fatal, Error/Exception, Warning, HTTP 5xx, HTTP 4xx 건수를 집계합니다. 로그 파일이 쓰기 중인 경우에도 읽기를 시도하며, 운영체제 잠금 등으로 열지 못한 파일은 읽기 실패 건수와 경로를 보고서에 표시하고 전체 점검 상태를 경고로 표시합니다. 로그 줄에서 날짜를 인식하면 설정 기간 내 줄만 계산하고, 날짜 형식이 없으면 파일 수정 시각으로 기간을 판단합니다. 제품 로그 위치에 맞는 경로를 등록하세요.

WEB 항목은 엔진 상태, WEB-WAS 연동, 요청 처리량, WEB 로그입니다. WAS 항목은 JVM Heap, Thread Pool, 장기 수행 Thread, DB Connection Pool, 배포 상태, Heap Dump, 기동 스크립트, WAS 로그입니다. DB 항목은 인스턴스·접속, 세션 한도, 데이터 영역, 백업, 아카이브 모드, 트랜잭션 로그, 복제 상태, 기타 사용자 쿼리입니다. 각 역할 블록에서 항목을 추가·삭제하고 항목별 스크립트를 연결합니다. 선택 버튼은 공통 모달을 열며, 모달 HTML은 `src/public/shared/fragments/script-template-picker-modal.html`에서 관리합니다.

기본 연결은 WebtoB 엔진 상태, JVM Heap, Windows MSSQL 인스턴스·접속 상태에 제공됩니다. 나머지 제품별 항목은 스크립트 관리에서 해당 점검 항목 템플릿을 먼저 작성한 뒤 서버 정책에서 연결하세요. 사용자 템플릿은 `$opsboxConfig.checks.rolePolicies`의 역할별 항목을 읽고 `$rolePolicyResults`에 `role`, `item`, `status`, `detail`을 기록합니다. 스크립트가 결과를 기록하지 않으면 보고서에 미수집으로 표시됩니다. 선택 변경은 **정책 저장** 후 다음 다운로드부터 적용되며, 점검 정책 아래에서 최종 JSON 구조를 확인할 수 있습니다. Linux는 현재 기존 Linux 스크립트 생성 방식을 사용합니다.

DB 인스턴스·접속 상태의 쿼리 선택은 해당 스크립트가 편집기에서 **실행 쿼리 템플릿 사용**으로 설정된 경우에만 선택 모달에 표시됩니다. 이 설정이 꺼진 스크립트에는 쿼리 목록이 나타나지 않습니다. 기본 보고서 데이터 계약인 `SERVER|이름|버전|에디션`과 `DATABASE|이름|상태|복구모델|크기MB` 형식으로 반환해야 합니다. `{{SERVER_IP}}`와 `{{SERVER_NAME}}` 변수를 사용할 수 있습니다. 지정하지 않으면 내장 상태 쿼리를 사용합니다.

사용자 SQL을 실행하려면 DB 정책에 **기타 사용자 쿼리**를 추가하고 스크립트 선택 모달의 다중 선택 목록에서 쿼리 템플릿을 하나 이상 고릅니다. 이 항목은 Windows MSSQL에서 실행되며, 각 쿼리의 성공 상태·출력은 점검 결과와 보고서에 별도로 기록됩니다. 사용자 쿼리 출력은 기본 인스턴스 보고서 계약과 별개로 텍스트 결과로 저장됩니다. 출력은 최대 200줄, 12,000자로 제한됩니다.

서버 상세의 기본 정보 영역 아래에 최신 점검 요약과 최근 점검 기록 5건이 작게 표시됩니다. 상세 보고서는 각 기록의 **보고서** 버튼으로 엽니다.

Windows MSSQL 연결은 기본적으로 서버 IP의 TCP 1433 포트와 Windows 통합 인증을 사용합니다. 다른 포트라면 실행 세션에서 `$env:OPSBOX_MSSQL_TARGET = '서버IP,포트'`를 지정하세요. 연결 시간 초과는 쿼리 실행 전의 네트워크 연결 실패이므로 SQL Server 서비스, TCP/IP 수신 포트, 서버 방화벽을 먼저 확인합니다.

MSSQL 데이터베이스의 이름/상태 열과 서버 속성 문자열의 데이터 정렬이 다를 수 있습니다. 문자열을 이어 붙이는 쿼리에서는 각 문자열 식에 `COLLATE DATABASE_DEFAULT`를 적용하세요. 제공 샘플과 기본 쿼리는 이를 적용해 서버/DB 간 데이터 정렬 충돌을 피합니다.

## 4. 점검 정책 설정

서버 상세 화면의 **점검 정책**에서 항목을 추가하거나 삭제한 뒤 **저장**을 누릅니다.

### 프로세스 점검

확인할 프로세스 이름을 등록합니다. 스크립트는 해당 프로세스가 실행 중인지 확인합니다.

### 디렉토리 점검

점검할 디렉토리 경로와 사용률 경고·위험 기준을 설정합니다. 경고 기준은 위험 기준보다 작아야 합니다.

### 특정 파일 크기 점검

파일 전체 경로와 경고·위험 기준 크기를 MB 단위로 등록합니다. 경고 기준은 위험 기준보다 작아야 합니다. 파일이 없으면 위험으로 판정됩니다.

### 포트 리스닝 점검

프로토콜(TCP 또는 UDP), 포트 번호(1~65535), 설명을 등록합니다. 같은 프로토콜과 포트 번호 조합은 중복 등록할 수 없습니다.

- TCP는 해당 포트가 서버에서 `LISTEN` 상태인지 확인합니다.
- UDP는 해당 포트에 소켓이 바인딩되어 있는지 확인합니다.
- 등록한 포트가 확인되지 않으면 보고서와 종합 상태에서 위험으로 표시됩니다.
- 이 점검은 서버 내부의 로컬 리스닝 상태를 확인합니다. 방화벽 통과 여부나 다른 장비에서의 원격 접속 가능성을 검사하지는 않습니다.

### HTTP 응답 점검 (Windows)

WEB/WAS 서버 상세의 HTTP 응답 점검에서 점검명, HTTP/HTTPS URL, 기대 상태 코드(100~599)를 등록합니다. Windows PowerShell 스크립트는 GET 요청을 최대 10초 기다리고 실제 상태 코드와 응답 시간을 기록합니다. 기대 코드와 다르거나 연결에 실패하면 종합 상태와 보고서에서 위험/실패로 표시합니다. Linux 스크립트 지원은 다음 단계에서 추가합니다.

WebtoB 4.1을 WEB 제품으로 등록하면 Windows 점검 스크립트가 PATH의 `wsadmin` 명령을 실행하고 `wi`, `ci -s`, `st -v`, `st -s`를 차례로 입력합니다. 실행 래퍼를 우선 사용하며, 실행 파일 위치에서 설치 경로를 판별할 수 있으면 `WEBTOBDIR`도 설정합니다. WebtoB 정보, 클라이언트 접속 수, 서버/서비스 상태 출력과 서버 상태 판정을 보고서에 기록합니다. `WEBTOBDIR` 오류가 계속되면 실행 계정에 환경 변수를 설정하고 새 PowerShell 창에서 다시 실행하세요. `RDY`가 없거나 `NRDY`·`BLK` 상태가 발견되면 각각 미수집 또는 위험으로 표시합니다. Apache, IIS, Nginx는 현재 공통 프로세스·포트·HTTP 점검으로 확인하며 제품별 관리 명령은 별도 연동이 필요합니다.

Windows WAS 스크립트는 JDK의 `jstat.exe`를 찾을 수 있고 실행 계정에 JVM attach 권한이 있으면 Java 프로세스별 Heap 사용률을 결과에 기록합니다. 70% 이상은 경고, 90% 이상은 위험으로 표시합니다. `jstat`가 없거나 권한이 없으면 해당 항목은 미수집으로 남습니다. JEUS 6의 Thread 정보를 확인하는 `ti`는 관리자 인증과 대상 컨테이너 정보가 필요해 아직 자동 수집되지 않습니다. Connection Pool, 배포 상태, 평균 처리시간과 기동 스크립트 변경 여부도 제품별 관리 API·설정 연동이 필요합니다. Node.js 런타임 지표와 Linux 수집은 후속 단계입니다.

### DB 엔진 점검 (Windows MSSQL)

DB 서버를 등록할 때 MSSQL, MariaDB, CUBRID, PostgreSQL 중 제품을 선택합니다. 현재 자동 SQL 점검은 Windows MSSQL 대상입니다. 서버에서 `sqlcmd`를 PATH로 실행할 수 있어야 하며, Windows 통합 인증(`-E`)으로 접속합니다. 스크립트는 서버명·버전·에디션, 데이터베이스별 상태·복구 모델·데이터 파일 크기를 읽기 전용 조회로 기록합니다. 데이터베이스 상태가 `OFFLINE`, `SUSPECT`, `RECOVERY_PENDING`, `EMERGENCY`면 위험, `ONLINE`이 아닌 다른 상태는 경고로 표시합니다.

DB 정책에서 인스턴스 상태, 세션·프로세스, 데이터 영역, 백업, 아카이브 모드, 트랜잭션 로그, 복제·이중화 항목마다 SQL 쿼리 템플릿과 실행 대상 MSSQL 인스턴스 목록을 지정합니다. 각 항목은 한 줄에 인스턴스 하나씩 입력하며, 그 항목의 쿼리가 입력한 모든 인스턴스에서 실행됩니다. 예: `localhost\testdb`, `localhost\인스턴스명`, `localhost,1433`. 사용자가 만든 쿼리는 기타 사용자 쿼리에서 여러 개 선택할 수 있고, 이 항목에도 별도 실행 대상을 입력합니다. 쿼리 결과는 컬럼과 행을 표로 표시합니다. 첫 컬럼 이름을 `__OPSBOX_STATUS`로 지정하고 `Healthy`, `Warning`, `Critical` 중 하나를 반환하면 점검 상태도 판정합니다. 현재 자동 쿼리 수집은 Windows MSSQL만 지원하며 `sqlcmd`와 Windows 통합 인증(`-E`)을 사용합니다. 각 항목의 초기 대상은 서버 IP의 TCP 1433이며, 구형 설정에 대상이 없으면 DB 인스턴스·접속 항목 대상을 대신 사용합니다. MariaDB, CUBRID, PostgreSQL과 Linux DB 쿼리 수집은 아직 지원하지 않습니다.

### 디스크 점검

별도 정책 입력 없이 실행 스크립트가 로컬 디스크 또는 로컬 마운트 지점을 모두 수집합니다. 디스크 사용률이 70% 이상이면 경고, 90% 이상이면 위험입니다. 종합 DISK 값은 가장 사용률이 높은 디스크의 값입니다.

## 5. 스크립트 실행과 결과 저장

1. 서버 상세 화면의 **점검 스크립트**에서 스크립트를 다운로드합니다.
   - Windows `.ps1` 스크립트는 Windows PowerShell 5에서 한글이 깨지지 않도록 UTF-8 BOM을 포함합니다. 이 수정 이전에 내려받은 파일이 있다면 새로 다운로드하세요.
2. Windows는 스크립트를 다운로드한 폴더에서 화면에 표시된 한 줄 실행 명령을 복사해 실행합니다. 같은 서버 ID로 여러 번 다운로드했으면 가장 최근 수정된 `<서버 ID>*.ps1`을 실행합니다.
3. 조립된 Windows PS1은 단계별 로그를 콘솔에 출력하고, 기본적으로 서버정보의 공유 경로 아래 `results/<연도>/<서버 ID>` 폴더에 결과 JSON을 저장합니다. 실행 명령의 `$resultDirectory = '';`에서 따옴표 안에 경로를 지정하면 해당 폴더에 저장합니다. 값을 비워 두면 서버정보의 공유 경로를 사용하며, 저장에 실패하면 스크립트 폴더로 대체 저장합니다. 콘솔에는 실제 저장 경로가 표시됩니다.
4. 웹 화면에서 최신 점검 결과 또는 보고서 이력을 다시 조회합니다.

스크립트는 서버의 프로세스·파일·포트 정보를 읽어 결과를 만듭니다. 스크립트를 실행할 계정에는 설정한 파일 경로와 시스템 상태를 조회할 권한이 필요합니다. 권한이 부족하면 일부 점검 항목이 누락되거나 미수신으로 나올 수 있습니다.

## 6. 보고서 확인

보고서 목록에서는 WEB, WAS, DB, 기타 유형과 서버가 기본으로 펼쳐져 날짜별 점검 이력을 바로 확인할 수 있습니다. 날짜, 상태, CPU·메모리·디스크 사용률과 보고서 링크가 표시됩니다. 서버명 또는 ID와 기간으로 검색할 수 있습니다.

상세 보고서는 유형별 점검표를 제공합니다.

서버와 프로세스의 가동 시간은 0이 아닌 단위만 년·월·일·시·분 순서로 표시합니다. 예를 들어 0년 1개월 26일은 `1개월 26일`로 표시하며, 값이 모두 0이면 `0분`으로 표시합니다. 저장된 상세 단위가 없는 과거 결과는 1년=365일, 1개월=30일 기준으로 분 값을 환산합니다.

- **WEB**: 웹 프로세스, 서비스 포트, HTTP 응답, 엔진·로그 경로, 파일시스템
- **WAS**: WAS 프로세스, 서비스 포트, 애플리케이션 HTTP, 로그·배포 경로, 파일시스템
- **DB**: DB 프로세스, 리스너 포트, DB 엔진·로그 경로, 파일시스템
- **기타**: 공통 CPU·메모리·디스크, 프로세스, 포트, 경로·파일 및 설정한 HTTP 응답 점검

제품별 JVM, DB 연결, 테이블스페이스, 백업, 외부 접속 등 현재 결과 데이터에 없는 항목은 보고서에서 `미수집`으로 표시합니다. 종합 진단 아래에는 공통 자원과 세부 결과를 볼 수 있습니다. 이전 점검 결과를 선택해 자원 사용률을 비교할 수 있고, **인쇄 / PDF**로 저장할 수 있습니다.

오래된 결과 파일에는 `disks` 또는 `ports` 상세 데이터가 없을 수 있습니다. 이 경우 해당 표에는 상세 정보가 없다는 안내가 표시됩니다. 새 정책을 적용한 스크립트를 다시 실행하면 신규 결과에 항목별 데이터가 기록됩니다.

## 7. 결과 파일 형식 참고

결과는 UTF-8 JSON입니다. 포트 항목에는 `port`, `protocol`, `listening`이 기록되고, Windows 결과에는 조회된 경우 `processName`도 포함됩니다. 디스크는 `disks` 배열에 장치·마운트 지점별로 저장됩니다.
