# 보고서 자원 사용 추세 그래프 설계 (짧은 설계)

작성일: 2026-11-21 · 규모: 작은 변경

## 목적
점검 보고서에서 숫자 비교(이전 점검 1건)만으로는 보기 어려운 **몇 주 동안의 흐름**을 그래프로 보여 준다. 디스크가 점점 차는지, 메모리가 늘어나는지를 한눈에 알게 한다.

## 목표 / 비목표 / 반목표
- 목표: 보고서 상세에 CPU·메모리·디스크(최대 볼륨) 사용률 추세선, 기간 2주·4주·8주(기본 4주), 주의 70%·위험 90% 기준선, 지금 보고서(●)·비교 점검(○) 표시, 점 위 값 표시·클릭 시 그 보고서로 이동, 다크 모드·인쇄 대응. 데모 데이터 8주.
- 비목표: 디스크 볼륨별 선, JVM Heap·DB 세션 등 역할별 지표, 대시보드 전체 서버 추세, 확대·이동.
- 반목표: 외부 라이브러리·CDN 사용, 인라인 스크립트(CSP 위반), 사용자 값이 HTML로 해석되는 것, 그래프 때문에 보고서 로딩이 느려지거나 인쇄가 깨지는 것.

## 방식
- 선택: **보고서 상세 화면에서 이미 불러온 점검 이력(`/api/results/:serverId`)으로 SVG를 직접 그림** (라이브러리 없음 — 사용자 결정).
- 검토했지만 안 쓴 것: 서버 집계 API(이력 수천 건 전까지 불필요), Chart.js/uPlot 포함(번들러·복사 단계·업데이트 부담, 그래프 몇 개에는 과함), 대시보드 추세(범위가 다름).

## 설계
- 위치: "자원 사용량 요약" 카드 아래 새 카드 "자원 사용 추세".
- 데이터: 같은 서버의 이력 중 `checkDate`가 지금 보고서 일시 이하이고, 그 일시부터 기간(14/28/56일) 안의 결과. 값은 `cpu`, `memory`, `disk`(이미 결과 해석 시 최대 볼륨 사용률). 숫자가 아니면(미수집) 그 점은 빼고 선을 끊음.
- x축: 실제 시각 비례(하루 여러 번 점검도 그대로), 눈금은 날짜(MM/DD). y축: 0~100%, 70%·90% 점선.
- 지금 보고서 점은 채운 점, 비교 선택 점검은 빈 점. 비교 선택을 바꾸면 다시 그림.
- 점 위에 마우스(키보드 포커스 포함): 일시·세 값 표시 상자. 클릭/Enter: 그 결과의 보고서로 이동.
- 결과가 1건 이하면 "추세를 그릴 점검 결과가 부족합니다." 안내.
- 그리기 코드는 순수 함수 모듈로 분리(점 좌표·눈금·선 경로 계산)해 node 테스트로 검증, DOM 생성은 createElement + textContent.
- 색: 계열 3색은 CSS 변수(밝은·어두운 테마 각각), 인쇄 시 밝은 색·값 표시 상자 숨김.

## 샘플 데이터
- 데모 기간 14일 → 56일(8주). 일 단위 증가 시나리오는 8주 끝에 지금과 비슷한 수준이 되도록 속도를 줄이고, "n일 전" 사건 시나리오는 그대로.

## 구현자에게 맡기는 것
- 정확한 SVG 크기·여백·글꼴 크기, 눈금 간격(기간에 따라 1~7일), 색 값(대비 확인).
