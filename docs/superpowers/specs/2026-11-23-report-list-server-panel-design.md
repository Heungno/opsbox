# 보고서 목록: 왼쪽 서버 목록 패널 (짧은 설계)

## 왜
보고서가 쌓이면 지금 목록(역할 → 서버 → 보고서 트리, 전부 펼침)에서 원하는 보고서를 찾기 어렵다. 사용자는 주로 **특정 서버의 보고서**를 찾는다.

## 목표 / 하지 않을 것
- 목표: 서버 관리 화면처럼 왼쪽에 서버 목록(검색 + 역할 탭), 오른쪽에 보고서(기간 조회조건 + 표).
- 목표: 서버를 고르지 않으면 모든 서버 보고서가 나온다(지금처럼 한 기간의 전체를 볼 수 있음).
- 하지 않음: 보고서 API·DB 변경, 보고서 상세·인쇄 변경, 페이지 나누기(필요해지면 따로).
- 실패로 볼 것: 서버 관리 화면의 왼쪽 패널 동작(검색·역할 탭·키보드·선택 표시)이 지금과 달라지는 것.

## 방법 (사용자 선택: 1)
1. **왼쪽 패널을 공통 부품으로 빼서 서버 관리·보고서 목록이 같이 씀** ← 선택. 두 화면 동작·모양이 늘 같음, 서버 관리 코드도 조금 바뀜.
2. 보고서 목록에 복사 — 빠르지만 코드 두 벌.
3. 트리 유지 + 패널만 추가 — 찾기 어려운 문제가 남아 제외.

## 설계
- **공통 부품** `src/public/shared/js/server-picker.js`: 서버 목록 불러오기(`/api/servers?includeInactive=1`), 검색(ID·이름·IP), 역할 탭(전체 + 공통코드 serverRoles, 건수·방향키), 목록 그리기(이름 / `ID · IP · OS · 미사용`), 선택 표시, 고를 때 콜백. 마크업은 지금 server-detail.html의 `template-list-panel`을 그대로 쓰고, 서버 관리 화면은 이 부품으로 바꿔 동작이 지금과 같아야 함.
- **보고서 목록 왼쪽**: 같은 패널. 서버 추가 버튼 없음, 새로고침은 둠. 목록 맨 위에 **"전체 서버"** 항목(처음엔 이것이 선택됨). 미사용 서버도 나옴(보고서가 남아 있으므로).
- **오른쪽**: 위에 시작일·종료일 + [검색][초기화], 그 아래 요약 카드, 그 아래 표 하나(최신순): 점검일시 · 서버(이름 + ID, 항상) · 상태 · CPU · MEM · DISK · [보고서 보기]. 제목은 "보고서 (전체 서버 · N건)" 또는 "보고서 (대민 포털 WEB #1 · N건)".
- **요약 카드 (사용자 요청)**: 지금 조회 조건(선택 서버·기간)에 맞는 보고서로 계산. 보고서 건수 · 서버 수(전체 서버일 때만) · 정상 · 경고 · 위험 · 최근 점검(일시 + 서버 이름). 서버 목록 화면의 `summary-card` 모양. 정상·경고·위험 카드를 누르면 표를 그 상태로 거르고, 다시 누르면 풂(Claude의 판단 — 위험 보고서를 빨리 찾게).
- **"전체 서버"일 때 범위 (Claude의 판단)**: 왼쪽 목록에 지금 보이는 서버들(검색어·역할 탭 적용)의 보고서. 예: 역할 탭 DB + 전체 서버 → DB 서버 보고서 전부. 이유: 왼쪽 필터가 오른쪽과 따로 놀면 헷갈림.
- **주소**: `/reports?serverId=WEB-01` — 새로고침·링크로 들어와도 선택 유지(history.replaceState, 서버 관리와 같은 방식). 없는 ID면 전체 서버.
- **좁은 화면**: 서버 관리 화면과 같은 배치 규칙(900px 이하에서 위아래로 쌓임)을 따름.

## 만드는 쪽에 남기는 것
- 보고서 API 호출 방식(서버별 호출 vs 전체 한 번 받고 거르기) — 지금 `/api/reports`는 serverId를 부분 일치로 거르므로, 한 번 받아 화면에서 거르는 쪽이 정확함.
- 표 CSS는 기존 `server-table`·`history-status` 재사용, 새 규칙은 `pages/reports.css`에 토큰만 써서.
- 화면 모양 비교: report-list 시나리오 기준은 새 화면으로 다시 찍음(일부러 바꾼 화면). server-detail 시나리오는 차이 0이어야 함.
